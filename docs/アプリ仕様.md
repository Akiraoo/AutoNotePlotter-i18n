# 譜面づくりのアプリ（仕様の相談の記録・2026-10-25〜）

試作5＋意思入れで、利用者が遊んで「人がマッピングしたような良い感じ」になった（2026-10-25）。この方向で、意思入れの画面を
ちゃんとしたアプリにする。このファイルは決めたこと・案・まだ決めていないことの記録（docs/意思入れ.md の続き）。

## 1. 決めたこと

### NLM とは別のアプリにする（2026-10-20 の「NLM から取り込むプラグイン」を置き換える）

- 理由: NLM はノーツを1つずつ置いて直す道具、こちらは区間に意図を付けて計算で作り直す道具で、1つのアプリでモードを切り替えると
  手で直したノーツと作り直しがぶつかる。NLM のプラグイン（nlm-rating の作り）は「exe を1回起動して JSON をやり取り＋NLM 側に
  そのプラグイン専用の画面と通信を足す」形で、何でも差し込める口は無い＝この規模の画面を入れると NLM 本体の大きな改修になる。
  音源分離（PyTorch＋Demucs・数 GB・GPU）も軽い譜面エディタに抱えさせるには重い。
- 流れは一方向: アプリで方針を決めて作る → NLM 用のファイル（.nlmf）を出す → NLM で微調整・ライティング。何度でも行き来してよい
  （下の「NLM とのやり取りの決まり」で、NLM で直した所は作り直しで消えない）。
- 形: まずは手元で動く Python のサーバー＋ブラウザの画面。最終的には NLM のように exe にまとめる。Node/npm は使わない。
- ライセンスは GPLv3 でよい（利用者・NLM のコードを写すため）。

### NLM とのやり取りの決まり（ファイルだけでつながる）

| NLM でのクリップ | アプリで作り直す時 |
|---|---|
| アプリが書いたまま（クリップの番号＝中身の指紋と一致） | 作り直す |
| 中身が変わっている（手で直した・動かした・分けた） | 残す |
| 名前に「固定」 | 残す |
| 自分で作った・貼り付けた（NLM が付けた番号） | 残す |
| アプリのレーンでクリップが無い所（NLM で消した） | 空のまま |
| ライト | 触らない |

- 「手で直したか」はクリップの番号に入れた中身の指紋で、ファイルの中だけで見分ける（外の控えと比べると、ファイルをコピーして
  別々に直した時に破綻する＝利用者の指摘）。NLM は保存し直してもクリップの番号と中身をそのまま残す（確かめた）。
- アプリは曲の頭から終わりまで区間ごとに必ずクリップを置く（ノーツの無い区間は空のクリップ）＝クリップが無い所は「消した」と分かる。
- 「作り直し」の印は NLM 側に付けない。どこを作り直すかはアプリの画面で選ぶ（全部／選んだ区間だけ）。
- マーカー（区間の名前・★・静・ドラム・歌・※・ここから）は今まで通り曲全体の方針を書く所。

### 作業の単位

- 1曲＝結果のファイル（.nlmf）1つ＋アプリの作業ファイル（意思入れ・設定・作った案の履歴）。
- 作業ファイルは .nlmf の隣に同じ名前で置く（例 `<曲>.intent-s1.automap.json`）。.nlmf をコピーする時は一緒にコピーする。
  （.nlmf の中には入れられない: NLM は保存の時にファイルの一番外側の知らない項目を消す）

### 曲の解析は NLM から写して、アプリだけで行う

- テンポ・無音追加の推定・拍の目盛り・構成の解析などを NLM から写し、NLM を動かさずに新しい曲を取り込めるようにする
  （今は NLM を見えない状態で動かしている）。アプリの作りとして独立している方が良い（利用者）。
- 写した元との同じ所を保つ方法（写した元の版の記録・差分を見る道具）を用意する。

### 画面の流れ

1. 曲を開く（結果のファイルを選ぶ／新しい曲を取り込む）
2. 編集の画面（タイムライン・右に指示の欄・右下に 3D）
3. 作り直す（全部／選んだ区間だけ／その区間の別の案）
4. NLM 用に保存して NLM で開く

### タイムライン

- NLM と同じ見た目・操作（拡大縮小・横スクロール・再生位置）。帯の中身は今の聞き比べのページと同じ（区間・曲の流れの表・
  くり返し・調のずれ・ドラムの勢い・途切れ・歌の広がり・楽器の多さ・旋律楽器・歌の大きさと高さ・ドラム・その他・ベース・
  意思入れ・量のライン・作った譜面）。

### 量のライン（全体のノーツの量）

- 10% きざみで十分（今は細かく動きすぎる）。
- 点の打ち方を楽に: キーフレームのように「ここから上げる」を置くと、そこから後ろがその値になる（次のキーフレームまで）。
- 不意のクリックで点が増えることがあるので、元に戻す（Ctrl+Z）は必須。

### 作り直しと別の案

- 全部か、選んだ区間だけか。「別の案」でテーマや種を変えた候補を 2〜3 個作り、3D で見比べて選ぶ。作った案の履歴から戻せる。
- 「どのテーマが良いか」は自動では決めない（数えられるのは振りの崩れ・警告・難しさ・曲の個性との合い方だけで、好みは人が決める）。

### 3D

- NLM の左上の 3D と同等にする（three.js・NLM のコードを写してよい）。

## 2. 案（利用者に確かめる）

- 量のラインの操作（下の 4 節）。
- 新しい曲の取り込み（音源分離から）は最初の版に入れず、作ったことのある曲で始める。
- 難易度は当面 Expert+ だけ。

## 3. まだ決めていないこと

- exe にまとめる時の作り（Python のまとめ方・音源分離の重い部品の扱い）。

## 4. 量のラインの操作の案

- 値は 50%〜200% を 10% きざみ（100% が自動のまま・2026-11-08 に上限を 150% → 200%）。
- キーフレーム: 帯の上でダブルクリックした所（小節の頭にそろう）に「ここからこの値」の点を置く。値は縦の位置（10% きざみ）。
  その点から次の点までは同じ値（段になる）。右クリックで「前の点からなめらかにつなぐ」に切り替えられる。
- 点はドラッグで動かす（横は小節の頭・Alt で拍の頭、縦は 10% きざみ）。右クリックの「消す」か、選んで Delete。
- 1回のクリックでは点を足さない（不意に増えないように。足すのはダブルクリックか右クリックの「ここに点を置く」）。
- 元に戻す（Ctrl+Z）・やり直す（Ctrl+Y）は、量のラインだけでなく意思入れの操作全部に効かせる。

## 5. NLM の曲の解析の中身（2026-10-25 に NLM のリポジトリを読んで調べた）と写し方の案

- 計算は Python のまとまり `song_analysis/`（`__init__.py`・`service.py`・`tempo.py`・`structure.py`）だけで閉じている。
  - テンポ（BPM）と無音追加の推定: `tempo.estimate()`（打楽器の成分の打点の周期・無音追加は `best_lead()`）。
  - 構成: `structure.analyze()`（区間 sections・細かい区切り segments・サビの候補 chorus・仮の名前 names）。1拍を4つに分けた目盛りで測る。
  - 調の推定は無い（転調はこちらの `music.py` が受け持つ）。波形・スペクトログラムの表示は JS 側の別の仕組み（解析とは別）。
- NLM のサーバーの `/__analysis/*`（音源を受け取る・ジョブを動かす・進み具合）から呼ばれるだけで、サーバーのほかの機能と共有する状態は無い。
- 画面（`js/analysis/song-analysis.js` など）は NLM のエディタの状態（BPM・無音追加・Music の配置・テンポパート・履歴）に深く絡むので、
  そのままは写せない。こちらの画面で作り直す。目盛りは、テンポが一定で Music を切り貼りしていなければ BPM と無音追加だけで作れる。
- 依存: librosa・numpy・scipy・scikit-learn・soundfile（m4a 等は ffmpeg）。PyTorch のような重い物は無い（exe にまとめると numba 等で
  大きくなる）。NLM は依存の版を上げる時に採点（テンポ 63 曲・構成 39 曲）で比べている。
- 結果は .nlmf の `analysis`（`{v, tempo, structure, names, grid}`）。`grid`（解析した時の目盛り）が今と違うと NLM は「解析し直して」と出す。
- ライセンスは GPLv3（NLM 全体）。解析の部分に他所から写したコードの記載は無かった（論文の方法の名前だけ）。

**写した（2026-10-26）**: `automap/song_analysis/`（NLM のコミット 70717ed・手を加えない・`SOURCE.md`）・包み `automap/analyze_song.py`・
道具 `tools/sync_nlm_analysis.py`（diff＝写した元との差・update＝写し直す・check＝NLM で作った元のプロジェクトと答えを比べる）・
`tests/test_song_analysis.py`。7 曲（曲C・曲E・作者の 5 曲）でテンポ（BPM・無音追加・ほかの値も）・区間・細かい区切り・サビの候補が全部一致。
1曲の解析は読み込みとテンポで 8〜12 秒・構成で 15〜34 秒。次は、これを使ってアプリから新しい曲を取り込む（音源分離＋解析＋譜面）。
**写し直した（2026-11-11）**: NLM のコミット 94dcf8e（答えを変えずに速く＝構成の多数決の固有値分解を 1 回に・HPSS を
`song_analysis.hpss` で 1 回に分けてテンポと構成へ渡せる）。包みの `analysis` は HPSS を 1 回だけ分けて両方へ渡す（NLM の service と同じ）。
写しの道具は NLM の作業中のファイルの行の終わり（NLM は autocrlf で直した物だけ CRLF）を LF にそろえて写す・比べる（`nlm_bytes`＝
指紋は NLM の git の中の中身と同じ）。

写し方の案（当時）:
- `song_analysis/` を**手を加えずに**こちらの別のフォルダへ写し、写した元の NLM の版（コミット）を記録する。こちらの都合の変更は
  外側の包み（音源の読み込み・目盛り・結果の形の変換）に置く＝NLM の元と比べやすく、更新は写し直すだけで済む。
- 写した元との違いを見る道具（NLM のリポジトリのファイルと比べて差分と版を出す）を作る。
- 写した物が NLM と同じ答えを出すかを、NLM で作った元のプロジェクト（解析の結果入り・5曲＋作者の 53 曲）で比べるテストを作る。
- こちらの `.venv` に librosa・scikit-learn を足す（NLM と同じ版）。

## 6. 3D の見え方（NLM の preview-v4 の移植・2026-10-25）

`app/static/preview3d/`。NLM の PREVIEW の窓（`preview-v4/preview-v4.js`・ArcViewer の移植・GPLv3）を、ステージの形（`env/*.json`・13 個）・

    （拍は絶対拍・テンポは一定）
  - `pv.setTime(拍, 再生中か)`・`pv.setTimeSec(秒, …)`（毎コマ呼ぶ。止まっている時も呼んでよい＝変化が無ければ描かない）
  - `pv.setNJS(n)`・`pv.setJD(d)`（JD を決めるとオフセットを計算し直す）・`pv.setNjsOffset(拍)`・`pv.jump()`（NJS・JD・反応時間・オフセット）
  - `pv.setEnvironment(名前)`・`pv.environments()`・`pv.setVisible({notes, lights, structs, ambient})`・`pv.setLook({bloom… 等})`・
    `pv.resize()`・`pv.render()`・`pv.dispose()`
- `nlmf-map.js` の `nlmfToMap(.nlmf の中身, {diff, muted})`: NLM と同じ読み方（タプル＝`_ENC` の並び・クリップの頭からの拍・見えるのは
  0 以上 len 未満・ミュートしたレーンは既定で隠す）で、上の `setMap` の形と NJS・色・ステージ・無音追加を返す。
- **使うページには import map が要る**（`three` と `three/addons/` → このフォルダの `js/vendor/three/`。ページに書くしかない。
  `importMap()` で中身を作れる）。canvas は入れ物いっぱいに重ねるので、入れ物に大きさを付ける。
- JD とオフセットの換算は preview-v4 の式（JD が 36 を超える間、半分にする）。NLM の画面の JD の表示（下限 1 拍）とは、とても短い時に少し違う。
- 確かめ: `test.html?nlmf=<URL>&t=<秒>&w=480&h=472`（リポジトリの一番上で `python -m http.server`）を見えない Edge で写し、
  NLM を見えない状態で開いて左上を PREVIEW にし同じ拍へ動かして写した物と比べた（曲C の拍 115.5・117.1）。
  ノーツの位置・大きさ・向き・ステージ・レーンの線まで同じ絵になった。JD 21.9・反応時間 686ms も NLM の表示と同じ。
- はまりどころ:
  - 見えない Edge でソフトウェア描画（`--use-angle=swiftshader`）にすると、まっすぐ縦の真ん中のレーンの線が消える（描き方の差）。
    `--use-angle=d3d11`（GPU）なら NLM と同じ。
  - ステージの読み込みは後から終わるので、止まっている間も毎コマ `setTime` を呼ぶ（呼ばないとステージが出ないまま）。
  - 譜面の拍→秒は `拍×60/BPM`（テンポパートは扱わない）。元の音源の秒に合わせる時は無音追加を足す（`nlmfToMap` の `lead`）。
- 確かめていない: ライト（lightEvents）の点き方（手元の作った譜面にライトが無い。preview-v4 のコードはそのまま）。

## 7. 最初の版（2026-10-25）

範囲（利用者と決めた）: 作ったことのある曲（分けた音と結果のファイルがある5曲）で、意思入れ → 作り直し → 3D で見る → NLM 用に保存。
新しい曲の取り込み（音源分離・NLM から写す曲の解析）は次の版（2026-10-26 にできた＝10 節）。

- 起動: `app/start.bat`（`.venv/Scripts/python.exe app/server.py`）。ブラウザで http://127.0.0.1:8765/ が開く（2026-11-11 から起動ごとの合言葉 `#k=…` 付き・
  23 節の「サーバーの出入りの守り」）。止めるのは `app/stop.bat` か
  画面の右上の「終わる」（作業ファイルを保存してから止める）か、起動した黒い窓を閉じる。最終的には pywebview で窓を出し exe に。
- 曲を開く: 上の選択。アプリが作り直すファイルは `out/<曲>.intent-s1.nlmf`。まだ無い曲は試作5（style-s1）を見せ、最初の作り直しで作る。
  作業ファイルは隣の `<曲>.intent-s1.automap.json`（無い時は前の聞き比べのページの `out/<曲>.intent.json` を引き継ぐ）。変えるたびに自動で保存。
