# 型のライブラリ（仕様・2026-10-26 に利用者と決めた）

譜面づくりの型（テーマ）は、今は手元の譜面（約 900 曲の Expert／Expert+）の「くり返される型」から集めている（`tools/library_themes.py` →
`cache/themes.json`）。手元の譜面は利用者が遊べる難しさ（★6 くらいまで）に偏っているので、**難しさで分けた広いライブラリ**を作り、
曲ごとに「どのライブラリの型を使うか」を選べるようにする。ライブラリ作り（譜面の取得・解析・データベース）は別のチャットで行う。
このファイルはその引き継ぎの仕様。

## 1. 決めたこと

- **元にする譜面**: BeatLeader の**ランク譜面**を基本にする。利用者が手元に入れている譜面は「手元」という別の出どころとして数える
  （手元の譜面もランク譜面なら同じ★で並ぶ。ランクでない物は★の近似＝nlm-rating で測り、近似と分かるようにしておく）。
- **難しさの物差し**: BeatLeader の★（難易度ごと。Pass／Tech／Acc も持っておく）。
- **作者で絞らない**: 1人の作者の曲数を抑えることはしない（利用者: 同じ作者を集めたことがあるが、曲ごとに大きく作り変えていて決まった型は
  あまり出なかった）。ただし後で作者ごとに絞れるよう、作者は記録しておく。
- **二段構え**: ①何でも入れておく**生データの置き場**（後から帯の切り方・作者・年などの軸を変えて作り直せる）と、②アプリが使う
  **探すためのデータベース**（生データから作る・軸を変えたら作り直す）。
- **取ってきた物は捨てない**: BeatSaver から落とした譜面は、音源・カバー画像も含めて**そのまま**保存する（利用者の Beat Saber の
  CustomLevels のフォルダにそのまま写せば遊べる形）。BeatSaver への負担を減らすため、一度取った物は使わなくても残す（後で解析し直す
  かもしれない）。容量は足りる見込み。
- **アップロード日で絞れる**: BeatSaver にアップロードされた日で絞り込める。古い譜面は理不尽な配置が多いらしいので、**まずは 2020 年から
  の物**を取りに行き、それで使い始める。後で範囲を広げたデータベースにする（段階を踏む）。
- **使う時にも年で絞れる**: 型を選ぶ時に、その型が出てきた譜面の公開年の範囲を指定できる。
- **型の区分は2つの軸**: 出てくる頻度（定番・よくある・珍しい）と、置き方の難しさ（やさしい・ふつう・難しい）。どこまで使うかを
  それぞれ選ぶ。
- **珍しい型は「決め」**: 1回しか出ない型は、くり返すテーマではなく、フレーズの終わり・区間の変わり目・山の音など**1回だけの場所**に
  使う。自動で作る時はそれで始める。後で意思入れ（区間の指示）で「この区間では珍しい型を使う」と指示できるようにする。
- **区間ごとにライブラリを選び直せる**: 難しさを直す時に、区間を指定して「この区間は別の帯・別の区分から型を取り直す」と指示できると
  細かく調整できる（意思入れの指示に足す）。
- **型と量は別々に選ぶ**（上の案の c）: 「型のライブラリ（★の帯）」と「目標の量（1秒のノーツの数）」を別の設定にする。量の初めの値は
  今の作り方のまま（今の譜面は 1秒 3.3〜4.5 ノーツ＝★4〜6 くらい）にし、足りなければ後で足していく。
  参考: 手元のランク譜面の1秒のノーツの数の中央値は ★〜4: 2.6・4〜6: 4.3・6〜8: 6.0・8〜10: 7.4・10〜12: 9.6。
  譜面の★は型より量で大きく決まる＝難しい帯の型を今の量で並べると「動きは難しめ・量は★5くらい」の譜面になる。
  量の目安としてできた（2026-10-26・docs/アプリ仕様.md 12 節）。データベースの中央値は ★〜4: 3.19・4〜6: 4.22・6〜8: 5.64・8〜10: 7.32・
  10〜12: 8.98（ランク譜面・2020 年以降・Expert／Expert+）。BeatLeader の PPv4 の★（6.8）では 3.13・4.18・5.73・7.42・9.30
  （データベースが無い PC の参考 `library_use.NPS_REF` もこの値に）。

## 2. 生データの置き場（何でも入れておく所）

置き場の場所は PC ごとの設定（このリポジトリには書かない・CLAUDE.local.md と設定のファイル）。git の管理外。中身の案:

```
<ライブラリの置き場>/
  maps/<key> (<曲名> - <作者>)/   … BeatSaver の zip を展開したそのまま（Info.dat・難易度の .dat・song.egg・cover。CustomLevels に写せば遊べる）
  meta/<key>.json                 … BeatSaver の譜面の情報（そのままの応答）: key・版の hash・曲名・作者（複数）・アップロード日・
                                    評価（好評価・不評価・スコア）・キュレーション・ランクの印・難易度ごとの NPS／ノーツ数／NJS など
  bl/<hash>.json                  … BeatLeader の譜面ごとの情報（難易度ごとの★・Pass／Tech／Acc・ランクになった日）
  fetch.log.jsonl                 … いつ何を取りに行ったか（条件・件数・失敗）。続きから再開できるように
```

- BeatSaver の版（hash）が変わった譜面は、古い版も消さない（`maps/<key>.<hash の頭>/` のように並べる案）。どの版を使うかは meta で分かる。
- 手元の譜面（CustomLevels）は写さず、場所と hash を記録して「手元」として読む（中身はそのまま）。
- 取りに行く時は BeatSaver・BeatLeader の負担を考えて、間を空ける（1 秒に 1 回くらい）・同じ物は二度取らない・失敗したら間を延ばす。

## 3. 探すためのデータベース（アプリが使う所）

SQLite（Python に入っている sqlite3）の1ファイル。生データから作り、軸や型の決め方を変えたら作り直す（作り方の版を記録する）。

| 表 | 中身 |
|---|---|
| maps | key・hash・曲名・作者（複数）・アップロード日・出どころ（ランク／手元）・BPM・長さ・評価 |
| diffs | 譜面ごとの難易度: 難易度の名前・特性（Standard だけ）・★（BL）・★が近似か・Pass／Tech／Acc・NPS・ノーツ数・NJS |
| swings | 難易度ごとの片手の振りの並び（拍・秒・手・マス・向き。スタック・スライダーは1振り）＝型を決め直す時の元（作り直しを速く） |
| patterns | 型: 種類（くり返し＝今のテーマの片手／両手の組・1回だけの並び）・形（右手にそろえた振りの並び）・形の数字（マスの数・移動・段・斜め・横の広がり）・置き方の難しさの点 |
| occurrences | 型がどの難易度に何回・どこに出たか（くり返しの回数・振りの間の秒と拍） |

- 頻度（定番・よくある・珍しい）と難しさの区分は、**使う時の絞り込み（★の帯・年・出どころ・作者）の中で数え直して決める**＝帯の切り方を
  変えてもデータベースを作り直さなくてよい。
- 置き方の難しさの点: 型そのものの形（腕の移動・向きの変わり方 45°／90°・斜め・腕の交差・振りの速さ）と、その型が出た譜面の★の
  中央値の両方を見る。
- 型の決め方は今の `tools/library_themes.py` の関数を使い回す（7 節の 1。片手の振りの並びで、2〜8 振りの同じ並びが続けてくり返されて
  いる所。振り下ろし・振り上げが交互の物だけ。点ノーツは除く。左手は左右反転で右手の形にそろえる）。1回だけの並びは、同じ長さの並びを
  曲じゅうから数える（何曲に出たか）。v4 の譜面・Noodle／Mapping Extensions・BPM が変わる譜面の扱いは今と同じく除く（後で考える）。

## 4. アプリと作る側で使う所（このリポジトリの側・別のチャットの後で）

- 曲ごと（作業ファイル）の設定: ライブラリ（出どころ・★の帯・アップロード年の範囲・作者）・型の頻度の上限・型の難しさの上限・目標の量。
  初めは今と同じ（手元・全部・今の量）。
- テーマの選び方（`automap/theme.py`・`style.py`）は `cache/themes.json` の代わりにデータベースを絞り込んで使う。曲の個性の目標の割合
  （斜め・外側の列・上の段）も、選んだライブラリの譜面から取る。
- 珍しい型は「決め」としてフレーズの終わり・区間の変わり目・山の音に1回だけ入れる（流れの計算には「決めたノーツ」に近い形で渡す）。
- 意思入れに足す指示: 「この区間は珍しい型を使う」「この区間はライブラリ（★の帯・区分）を変えて取り直す」。
- 作った譜面の★を nlm-rating で測って画面に出す（選んだ帯に近づいたかを見る）。

**決めた（2026-10-26 利用者）**:
- アプリの新しい曲の既定は **ランク譜面（`sources=['ranked']`）・時期は曲ごとに自動（2026-11-03 から・6.9。前は 2020 年以降）・★〜8（PPv4.1 からは ★〜8.5・6.11）**（Expert／Expert+）。★で絞らないと難しい譜面の型が
  中心になり「動きだけ難しい★5くらい」になりがち・★〜6 は型が少なすぎる（6.7 の数: ★〜8 で 512 曲・片手の型 283・両手 163）。
- **今の曲（作業ファイルにライブラリの設定が無い曲）は今の `cache/themes.json` のまま**（気に入っている譜面が勝手に変わらない）。
  `cache/themes.json` は作り直さない。新しく取り込む曲からデータベースを使う。今の曲も画面で選べば切り替えられる。
  → **2026-11-09 に「今の型」（`cache/themes.json`）ごと除いた**（6.12・利用者「リリース用の BeatLeader のメインのデータベースからだけの
  作成に絞り込んでよい」）。設定の無い曲は新しい曲の既定に読み替える（その時の曲はどれももうランク譜面の設定だった）。
- 進める順: ①曲ごとのライブラリの設定（画面・作る側の切り替え・曲の個性の目標も選んだ譜面から）②作った譜面の★を画面に
  ③珍しい型を「決め」に。その後に ④意思入れの2つの指示 ⑤目標の量。
- ④ の「この区間は珍しい型」（2026-10-26 利用者）: ★で絞ると型が少なくなるのは仕方ない。その代わり、**少ない曲にしか出ない型（1回しか
  出ていない物まで）に広げて使うのを、区間ごとに作り直す時に選べる**ようにする（曲全体の「型の頻度の上限」とは別に、区間の指示で
  広げる・別の案でも選べるとよい）。そのため、テーマに使う型のしきい値（何曲以上に出た型か）は引数で変えられる作りにする。
- **つないだ（2026-10-26）**: ①曲ごとのライブラリの設定（作業ファイルの `library`・画面の「ライブラリ」・テーマに使う型の最小の曲の数は
  データベースでは曲の数に合わせた同じ割合・頻度「珍しいまで」は 2・2・曲の個性の目標は選んだ譜面と手元の譜面の差だけずらす）②作った
  譜面の★（`automap/rating.py`・上の列）。中身と確かめた数字は docs/アプリ仕様.md 12 節。区間の点検（同じ 12 節）も型のデータベースの
  swings を使う。
- **③珍しい型の「決め」（2026-10-26・`automap/kime.py`）**: 型のデータベースの曲（compose `--library`）だけ。1回だけの並び（once）の
  「珍しい」（無ければ「よくある」）を、途切れの前（点 3.0・ドラムだけの途切れ 2.5）・区間の変わり目の直前（2.0・次で盛り上がる時 +0.5）・
  山の音（1.5）・曲の終わり（1.5）・フレーズの終わり（1.0）に 1 つずつ（30 秒に 1 つまで・時間で等分した枠ごとに 1 つ・1 区間に 1 つ・
  12 拍あける）。場所の直前の、その手の続く 4 振り（間は 2 拍・1.2 秒まで・一番長い間が一番短い間の 2 倍まで）。1回目の流れの計算の
  結果の手と振りの向きに合う型だけを選び（左手は左右反転）、決めたノーツ（重み 2.5。同じ振りは 4・残したノーツは 20）として計算し直す。
  型の点: 振りの間の比・曲の個性（流れの計算と同じ目標の割合）・難しさ（盛り上がりの段階 0 では「難しい」を使わない）・もう片方の手との
  ぶつかり。腕が交差する型・真ん中の段の中央2列を含む型・両手同時でもう片方の側に出る型は使わない。1曲の中で同じ型は使わない。
  同じ振り・残したノーツの前後 2 拍・--only の外には入れない。置き方の指示には逆らわない型だけ・案 k の区間は場所の点を半分。
  **決めの前後 2 拍の外は 1回目の結果に弱く留める（重み 0.2）**: 留めないと、手の割り振りの道が変わって点数がほぼ同じ別の道のまま戻らず、
  意思入れの無い曲で曲の 6〜8 割が変わった（揺らぎの直しの後も）。`--no-kime` で切る。報告に「## 決め（珍しい型）」。
  確かめ（6 曲の写し・同じ時点のコードで --no-kime と比べた）: 決め 31 か所・置けたノーツ 128/132（97%）・違う拍は決めの前後 8 拍の中
  （外は 0〜1）・崩れ 0・NLM の振りの警告 0・同じ振りの手本どおりは変わらない。cache/themes.json の曲は何も変わらない。NLM で開ける。
  選ばれた型は「珍しい」の 4〜5 曲に出た物（once は区分ごとに曲の数の多い順に 1000 まで＝2〜3 曲の型も使うなら `once_limit`）。
  残り: 意思入れ「この区間は珍しい型」は `kime.choose(..., want=[(b0, b1)])` につなぐ（区間の中の場所の点 +3・数の上限の外）。
  試作4・5 の作り（--form）では山の音は★のマーカーからしか出ない。`--only` の数の上限は区間の長さで数える。タイムラインに決めは
  まだ出していない。
- **④を作った（2026-10-26）**: 区間の指示 `rare: 1`（珍しい型まで＝テーマのしきい値を 2・2 に下げた束から、区間の小節だけ選び直す・
  案 k と一緒なら広げた束の中で案 k・小節ごとに案と別々に勝ち負け・頻度を絞った曲は珍しいまでで書き出し直す）・`kime: 1／-1`
  （`kime.choose` の want／avoid。入れる区間に上限の外で 1 つ・入れないが勝つ・珍しい型までの区間は既定で入れる側・型のデータベースの
  曲だけ＝今の型の曲では報告と指示の欄に「効かない」）。束の型は cache/themes.json 238→632・★〜8 206→320。性格ごとに選ぶ 24 テーマの
  うち曲の束に無い型が 15〜21。区間の中のテーマはほぼ広げた分（2/2・3/3）・崩れ／警告 0・指示の無い曲の答えは変わらない。
  「この区間はライブラリ（★の帯）を変えて取り直す」も作った（2026-10-26・`set.band`・`library_use.export_band`・`band_stars`・
  docs/アプリ仕様.md 12 節の「区間の★の帯」）。決め −1 で空いた枠は
  曲の別の所の決めになる。
- つなぐ口（2026-10-26）: compose `--library <絞り込みの JSON>`（`automap/library_use.py`・無ければ `--themes`＝2026-11-09 に除いた・6.12）・報告に「型の出どころ」・
  アプリは作業ファイルの `library` を `server.COMPOSE_EXTRA` で渡す（`app/library.py`）。

   手元の譜面も「手元」として登録する。どこまで取るか（件数・帯）は、取りながら利用者と決める。
2. （別のチャット）生データから探すためのデータベースを作る（振りの並び・型・出てきた所）。

4. 後で、取る範囲（年・帯）を広げたデータベースにする。

## 6. 作った物（2026-10-26・別のチャット）

### 6.1 道具と動かし方

- `tools/library_build/fetch.py` — 生データを取る（`list`＝BeatLeader のランク譜面の一覧・`local`＝手元の譜面の登録・`meta`＝BeatSaver の
  情報・`maps`＝zip を取って展開・`rate`＝★の近似・`status`＝件数と大きさ・`all`＝順に全部）。
- `tools/library_build/build_db.py` — 生データからデータベースを作る（手元の譜面を登録し直してから作る。ネットには行かない）。
- `automap/library_db.py` — 読む口（7 節の 2）。
- 場所は PC ごとの設定 `app/config.local.json`（git の管理外）: `library_root`＝生データ・`library_db`＝データベースのファイル（無ければ
  `library_root` の下の `library.sqlite`。生データは HDD・データベースは SSD のように分けられる＝データベースは作り直しのたびに読む）・
  `custom_levels`＝手元の譜面・`nlm_rating_exe`＝★の近似に使う nlm-rating・`library_own`＝自分で書き出した手元の譜面のフォルダ名の型の
  一覧（例 `["<書き出しの頭>-*", "!<手で打った物>"]`・「!」で始まる型に合う物は、ほかの見分け（6.3）が当たっても除かない。作り直しで印を付け直す）。環境変数 `AUTOMAP_LIBRARY`（データベース）・
  `AUTOMAP_LIBRARY_RAW`（生データ）・`AUTOMAP_CUSTOM_LEVELS`・`NLM_RATING_EXE` でも渡せる。

```
python -I tools/library_build/fetch.py all --skip-local   # 一覧 → 手元の登録 → BeatSaver の情報 → 2020 年以降のランク譜面で手元に同じ版が無い物 → ★の近似
python -I tools/library_build/build_db.py                 # データベースを作る（2,000 曲ほどで 1 分足らず）
python -I tools/library_build/fetch.py status             # ★の帯・年ごとの件数と置き場の大きさ
```

`maps` の絞り込み: `--since 2020`（アップロード年・既定）・`--stars 下 上`（Standard のランクの難易度の★）・`--skip-local`（手元に
同じ版がある物は取らない）・`--limit N`・`--dry`（数えるだけ）。

### 6.2 生データの置き場（2 節の案から変えた所・足した所）

- `maps/<key>.<hash の頭 8 文字> (<曲名> - <作者>)/` — 版が1つでも hash の頭を付ける（後で版が増えても名前が変わらない）。zip の中身
  そのまま（CustomLevels に写せば遊べる）。zip は捨てる。
- `maps_index.json` — 取った版（hash → フォルダ・取った日・大きさ・中身の hash が合ったか）。ここにある版は二度取らない。
- `meta/<key>.json`（BeatSaver の応答そのまま）・`meta/_hashes.json`（版の hash → key。BeatSaver に無い版も記録して二度聞かない。
  版で見つからない手元の譜面はフォルダ名の key でも聞く）。
- `bl/<hash>.json`（BeatLeader のランク譜面の一覧の応答のうち、その版の難易度の分そのまま）・`bl/_ranked.json`（索引）。
- `local/index.json` — 手元の譜面の登録（場所・`os.listdir` の並び・版の hash・中身の目印）。写さない。中身が変わったフォルダだけ hash を計算し直す。
- `rating/<hash>.json` — BeatLeader の★が無い難易度（手元のランクでない譜面・ランク譜面のランクでない難易度）の★の近似（nlm-rating の応答

- `fetch.log.jsonl`（いつ何を取ったか・失敗）・`tmp/`（書きかけ。次に動かす時に消す）。
- 取り方: 同じ相手には 1 秒あける・429／5xx・つながらない時は 5→15→45→120→300 秒待ってやり直す・続けて 5 回失敗したら止める・

### 6.4 書き出し（`export_themes`）の決めごと

- `maps` は今の themes.json と同じく**曲（フォルダ）の数**（7 節の 2 の「何難易度」ではない。今と同じ数にするため）。難易度の数は足した項目 `diffs`。
- 出どころ: `local`＝手元のフォルダ全部（同じ譜面の複製も別々に数える＝今と同じ）。`ranked`＝BeatLeader のランクの難易度だけ・同じ版は1つ。
  両方（省略時）は手元の全部＋手元に同じ版が無い取った物。**自分で書き出した手元の譜面（`own`）は既定で除く**（自動で作った譜面が手元の型に
  混ざらないように・2026-10-26 利用者）。入れるのは `include_own=True`（今の library_themes.py と比べる時）。`on_beatsaver=True` は
  BeatSaver に無い手元の譜面を全部除く（ゲームに入っている曲・BeatSaver から消えた譜面も除く）。
- 同じ曲の数の型は、最初に出てきた順（今の `library_themes.py` の並び）＝書いたファイルは今の作り方の themes.json と順まで同じ。
- 頻度の区分（絞り込みの中で数え直す）: **定番**＝曲の数が max(5, 曲の 5%) 以上・**よくある**＝max(3, 1%) 以上・それより少ない＝**珍しい**。
- 置き方の難しさの点＝形（移動×0.5＋向きの変わり方（真逆への振り 0・135° 1・90° 2 の平均）＋斜め×0.5＋左端の列（右手の形で腕の交差）＋
  上の段×0.5）＋振りの速さ（同じ手の振りの間が 0.3 秒より 0.1 秒短いごとに 1）＋★の中央値×0.2。区分（やさしい・ふつう・難しい）は
  絞り込みの中の三分位。`hard` に点と内訳を入れる。
- 1回だけの並び（`once`・型の決め方の版 1）: くり返し（runs）の外の、点ノーツを含まず振り下ろし・振り上げが交互の片手の 4 振り（右手の形・
  輪にしない）。何曲に出たかで頻度の区分。`gap`・`sec`・`stars` は難易度ごとの値の平均（中央値ではない＝速さのため）。書き出すのは
  2 曲以上に出た物（`once_min`）を、区分ごとに曲の数の多い順に 1000 まで（`once_limit`）。`once=False` で出さない。
- 足した項目: 各型に `stars`（出てきた難易度の★の中央値・近似を含む）・`years`（[最初, 最後] のアップロード年）・`diffs`・`freq`・`hard`。
  全体に `once`・`library`（作った日・版・絞り込み）。

### 6.8 BeatLeader の PPv4 で★を取り直した（2026-10-29）

## 7. 今の作りとのつなぎ方（ずれないための約束・別のチャットが必ず守る）

（2026-10-26 の約束の記録。作る側は 2026-11-09 から型のデータベースだけを読む＝6.12。`export_themes` が `tools/library_themes.py` の書く形と
同じ型を出す約束と一致のテストはそのまま）

今の作る側は、型を `cache/themes.json`（`tools/library_themes.py` が作る）から `automap/theme.py` の `load_themes` で読んでいる。
新しいデータベースは、**今の形をそのまま出せる**ことを最初の約束にし、足す物は今の形に項目を足す形にする。

1. **型の決め方・そろえ方は今の関数を使い回す**（書き直さない）: 振りの読み方は `tools/library_stats.py` の `load`・`find`・`parse_diff`、
   片手の振りの並び・くり返しの見つけ方・形のそろえ方（左手は左右反転して右手の形・振り下ろしから始まる回転で辞書順が一番小さい物）・
   形の数字は `tools/library_themes.py` の `parity`・`to_r`・`canon`・`hand_swings`・`runs`・`shape`。直す必要があれば、直した上で 3 の
   比べのテストを通す。振りは `(x, y, d)`（x 0〜3・y 0〜2・d 0〜7）の並び。
2. **今の形を出す口**: このリポジトリに `automap/library_db.py` を作り、次の関数を持たせる（読む側。アプリと作る側はこれだけを使う）。
   - `open_db(path=None)`: データベースを開く。場所は引数か、環境変数 `AUTOMAP_LIBRARY`、無ければ `app/config.local.json` の `library_root`
     （その下の `library.sqlite`）。
   - `export_themes(filters, out_path=None) -> dict`: 絞り込みの中で数え直した型を、**`cache/themes.json` と同じ形**（`songs`・`ranks`・
     `hands`＝`[{cycle, cells, move, row, diag, width, maps, runs, gap, sec}]`・`pairs`＝`[{a, b, shape_a, shape_b, maps, runs, gap, sec}]`）で返す。
     `maps` は絞り込みの中で何難易度に出たか。足す物は項目を足すだけ（各型に `stars`（出てきた難易度の★の中央値）・`years`・`freq`
     （定番／よくある／珍しい）・`hard`（置き方の難しさの点と区分）、1回だけの型は新しい鍵 `once`＝`[{seq, maps, …}]`）。今の
     `load_themes` は知らない項目を無視するので、`export_themes` の結果をファイルに書けばそのまま今の作りで使える。
   - `filters`（辞書・全部省略可）: `sources`（`'ranked'`・`'local'`）・`stars`（`[下, 上]`）・`years`（アップロード年 `[から, まで]`）・
     `mappers`／`exclude_mappers`・`diffs`（`['Expert', 'ExpertPlus']`）・`freq`（使う頻度の上限）・`hard`（使う難しさの上限）。
   - `diff_stats(filters) -> dict`: 絞り込んだ難易度の、曲の個性の目標に使う割合（段・列・向き・1秒のノーツの数・振りの速さの分布。
     `tools/library_stats.py` の `analyze` と同じ数え方）。`automap/style.py` が選んだライブラリに合わせて目標を変える時に使う。
3. **ずれていないかの確かめ（テスト）**: 手元の譜面だけ（`sources=['local']`・Expert／Expert+）で `export_themes` した結果が、今の
   `cache/themes.json` と同じ型・同じ数（`hands`・`pairs` の `cycle`・`a`・`b`・`maps`・`runs`）になること。ファイルが無い環境では飛ばす。
   小さな作り物の譜面（数曲ぶんの .dat）での単体のテストも置く（git に入れてよいのは自分で作った物だけ。他人の譜面は入れない）。
4. **データベースの版**: 表の形の版（`schema_version`）と、型の決め方の版（`extract_version`）を記録する。決め方を変えたら版を上げて
   作り直す。`automap/library_db.py` は合わない版を読んだら分かるように止める。
5. **受け持ちの分け方**: 別のチャットが作るのは、取ってくる道具・生データ・データベースを作る道具（`tools/library_build/` の下）・
   `automap/library_db.py`（読む側）・そのテスト・この文書の書き足し。作る側（`automap/theme.py`・`style.py`・`__main__.py`・`intent.py`）と
   アプリ（`app/`）はこのリポジトリのいつものチャットがつなぐ（`load_themes` を `export_themes` に切り替える・設定の画面・意思入れの指示）。
   どうしてもそちらを触る時は、変えた所を報告に書く。
6. **重さ**: `export_themes` は作り直しのたびに呼ぶので、数秒以内に返る作りにする（難易度ごとの数を先に数えておき、絞り込みは SQL で足し合わせる）。
